Network Fault Analytics

A proposed method for exploring how network alarms relate across time and location.

On this page

  1. Problem
  2. Proposed data & method
  3. Findings & limitations
  4. Reproducibility

Problem

Network operations can generate many alarms around the same time. A useful first step is to organize related events so an analyst can investigate possible relationships without assuming one event caused another.

Proposed data & method

Use synthetic events with a timestamp, site identifier, and alarm category. Group by site and a defined time window using SQL or Python, inspect sequences, and compare candidate clusters against the original event list.

Illustrative synthetic events
Time Site Event
09:00 Site A Power alert
09:04 Site A Link alert

The timing puts both alerts in the same investigation. Equipment logs can help verify whether they share a cause.

Findings & limitations

Measured findings are pending. Window selection, missing events, and clock differences can affect groupings. Domain context and independent evidence are needed to assess causality.

Reproducibility

The next step is to publish a synthetic dataset, an analysis script, and repeatable results.
